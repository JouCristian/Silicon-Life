# 本地 HEX 与初始配置

所有文件通过浏览器 File API 读取，不上传服务器。输入上限 **64 KiB**（原始文件 / UTF-8 文本），展开前检查容量。解析器位于 `src/io/hex.ts`，与 React、DOM 和 CPU 执行独立。

## 支持的语法

```text
v2.0 raw
# # 后至行尾为注释
00500093 00700113
002081b3
```

也支持不带头部的纯十六进制列表、BOM、多行、空格、大小写及可选 `0x` 前缀。仅 `v2.0 raw` 支持十进制正整数重复次数：`16*00000000` 展开为 16 个零单元。零次、负数、浮点次数、过长数值和容量溢出均拒绝，不截断。单元最多为 2 或 8 个十六进制数字；不足位数可省略前导零。

**不支持** Logisim v3.0、地址标记 / 地址数据对、Intel HEX、二进制、ELF、汇编文本、带校验和的文件。不要将 ROM 与 RAM 文件混用。

## ROM

- 32-bit 单元，起始 PC=0，相邻地址 +4，容量 256 条；编辑器允许空白程序，文件导入要求至少一条。
- 仅接收 Core 已实现的 ADDI、ADD、LW、SW、BEQ。未支持项报告准确的第 N 条、机器码与译码原因。
- 选择文件 → 校验 → 文件名 / 格式 / 宽度 / 数量 / 前 8 条地址和反汇编预览 → 确认。可以替换，也可追加。追加容量按完整程序校验；失败不改变原程序、架构状态或 Trace。
- 确认后生成自定义程序，复位执行历史与播放时间线，保留初始寄存器和 RAM。该结果作为新的自定义初始程序；后续编辑可恢复它。
- BEQ 的立即数是相对于该指令 PC 的字节偏移。插入、删除、移动、追加均**不会自动修改立即数**；完整列表显示目标与范围 / 对齐提示。范围外目标是提示，执行仍遵守既有 Core 规则。
- 导出为标准 `v2.0 raw`，每行 8 位十六进制，逐项往返一致。空程序不导出。

`examples/arithmetic.hex` 直接在「ROM HEX 导入 / 导出」确认导入，运行后 x1=5、x2=7、x3=12、PC=12、提交 3 条。

## RAM

RAM 为 1024 字节、小端序。导入需选择 **数据单元宽度**与 **CPU 起始字节地址**（默认 0），二者不是同一个地址单位。

| 模式 | 第 i 个单元的 CPU 字节地址 | 对齐要求 | 最大单元数（起始 0） |
| --- | --- | --- | --- |
| 8-bit | start + i | 任意字节 | 1024 |
| 32-bit | start + i × 4 | start 按 4 字节对齐 | 256 |

起始地址和展开数据总字节数必须全部在 0…1023 内。确认导入采用 **整份替换初始 RAM，未指定字节全部清零** 策略；不会替换 ROM。32 位 `11223344` 在低到高地址存为 `44 33 22 11`。导出初始 RAM 的全部 1024 字节，可选 8/32 位宽度；重新导入选择相同宽度、地址 0。

初始 RAM 和运行 RAM 分离。CPU 执行后的 SW 只改变运行 RAM，Δ 与字节高亮显示两者差异；Reset 恢复初始 RAM 和初始寄存器。改程序、切换预设和回放均不清除初始配置。刷新页面会丢失当前会话配置，请先导出。

手动写入接受十进制整数或 `0x` 十六进制。8 位范围 0…255，32 位范围 −2147483648…4294967295（负数转为补码）；拒绝空值、指数、浮点、NaN、越界、未对齐及静默截断。地址也接受十进制或 `0x`，最终按字节检验。

仅在 retired=0 且未运行 / 播放时可配置初始 RAM 与寄存器。执行后先复位。寄存器 x0 只读恒零。运行 / 初始视图、8/32 位观察宽度和 DEC/HEX 展示可随时切换。

## RAM 示例操作

`examples/memory-init.hex`：

```text
v2.0 raw
16*00000000
0000002a
```

1. 复位 CPU，打开「RAM HEX 导入 / 导出」，宽度 32-bit、起始字节地址 0。
2. 选择文件；预览共 17 单元，确认导入。单元 16 对应 CPU 字节地址 64，值为 42。
3. 新建空白程序，新增一条 LW，rd=x3、rs1=x0、立即数=64，应用后单步，x3=42。或将纯机器码 `04002183` 存为 ROM HEX 导入。
4. 若写 SW 更改运行内存，复位后 RAM[64] 恢复为 42。修改 / 重载程序同样保留此初始值。
